### qeval: noise and an extractor bug

The single-run qeval floor of 74/75 failed final3 (72), A (73, 71) and Q (73, 73) in the morning gates. A separate
study repeated the runs:

| Stack | qeval x3, old extractor | qeval x3, fixed extractor |
|---|---|---|
| final2 | 73 / 75 / 72 | 74 / 75 / 74 |
| Q | 73 / 74 / 73 | 74 / 75 / 75 |
| A | 74 / 74 / 73 | not rescored |
| C | | 75 / 74 |

- Greedy output is not reproducible within a boot on this stack (the same prompt flips between two answers), so
  a single qeval run moves by 2-3 points.
- `extract_final_number` took the last number in the reply, so a correct answer followed by a restatement could be
  scored wrong. It now prefers the last line that holds only a number, the form the prompts ask for. Rescoring 360
  repeated runs of the flaky tasks took reason_r12 (32 misses), reason_r4 (12) and math_m4 (14) to zero.
- Substantive misses over 60 repeats of each flaky task: final2 49/360, Q 45/360, A 39/360 (math_m3, math_m9,
  json_count): no stack is worse than final2.

**Quality rule from this release on:** the long-prompt KL panel and the teacher-forced KLD are the primary gates;
qeval is run three times with the fixed extractor and compared with a reference measured in the same window.

## Device-side selection: one λ

With device-side selection, the host and the device each kept their own λ (the truncation policy's value per token).
They drifted apart, so 0.3-0.8 % of one-request decisions picked a different verify length than host truncation
would have (both paths are lossless; the speed effect was ±0.01 % in a replay). This release keeps one λ per graph
set: device steps publish it (8 bytes, stream-ordered after the parent graph), the next host decision adopts it and
writes its update back. An offline replay over 29k decisions per scenario gives 0 differing lengths outside fallback
steps. On the fleet (C): armed 4/4, 0 build failures, 480 G1 buffer checks all identical (MLA valid region
included), 0 device/host and 0 rank mismatches over 8000 device steps, λ sync pull 1 / push 327, qeval 75 and 74,
T > 0 scan clean.

## Known follow-ups

- Device-side selection covers one request only; batches use host truncation.
- A qeval reference must be measured in the same window; single runs are not a gate.
